# Loader — локальный кряк

Оригинальный `Loader.exe` (v1.0.6.0, UI 1.0.14) проверяет ключ на своём сервере
(`https://95.85.230.17`, `https://138.124.40.179`). Здесь лежит обвязка, которая
подменяет сервер на локальный и снимает проверки подписи релиза.

Подпись **`crac BY armore3`** стоит в заголовке окна загрузчика и плашкой в
углу его UI (её рисует `LoaderCrack.exe`), а также в консольном баннере
`start.bat`. Меню самого чита (`Insert`) живёт внутри упакованного VMP
`RobRun.exe` — до него добраться нельзя, поэтому подпись там честно не стоит.

## Проверка на новом ПК: `SETUP.bat`

`SETUP.bat` ничего не меняет и не качает — только проверяет и говорит, готов
ли ПК и в каком режиме он будет обновляться: Python, WebView2, наличие
`Loader.exe` / `LoaderCrack.exe` / `api.py` / `packages\1.zip`, `hwid.txt`,
`license.json`, и живой запрос `update.ps1 -Check` к вендору. В конце пишет
`now run: start.bat`.

## Перенос на другой ПК (честно)

Сам кряк (`api.py` + `LoaderCrack.exe`) принимает любой ключ локально, поэтому
**интерфейс лоадера заведётся на любой машине**. Но **билет на запуск чита**
выписывает реальный сервер вендора, а он жёстко привязал ключ из
`license.json` к одному железу. Проверено живьём: с чужим `hwid`
`POST /api/v1/auth` отвечает `403 Запрещено`.

Отсюда два режима:

| где запускают | что происходит |
|---|---|
| ПК armore3 (свой `hwid`) | всё как есть: `update.ps1` тянет сборку прямо с вендора, `inject.ps1` берёт настоящий билет. |
| любой другой ПК | вендор отказывает `403`, `update.ps1` ставит `logs\vendor_down.flag`, и обновление передаётся **официальному лоадеру** (`start_loader.bat`). Запуск чита идёт на уже установленной сборке; настоящий билет выписать нельзя, пока у человека нет своего ключа. |

Поэтому «скачал папку — работает точно так же» верно только для ПК, у которого
есть доступ к ключу. Что реально переносимо и важно:

* `hwid.txt` — id именно этой машины. Его считает сам оригинальный
  `Loader.exe` и присылает в `api.py` при первом входе; `api.py` сохраняет
  его в `logs\loader_hwid.txt`, а `SETUP.bat` переносит в `hwid.txt`. Раньше
  `hwid` лежал внутри `license.json` — из-за этого папка была бесполезна на
  другой машине.
* `loader_key.txt` — **официальный** ключ для запасной цепочки
  `start_loader.bat` (образец рядом: `loader_key.example.txt`). На чужом ПК
  скопируй образец в `loader_key.txt` и впиши свой официальный ключ: тогда
  официальный лоадер сам скачает обновление, а кряк подхватит новый пакет.
* `packages\1.zip` уже лежит в папке, поэтому запуск не зависит от сети.

## Ошибка «Не удалось обновить лоадер. Запустите его снова» — исправлено

Текст живёт в `GameLoader.SelfUpdate.HandleArguments` (ветка `--apply-loader-update`),
но в UI он всплывал из-за контракта локального API:

```
SelfUpdate.Check:  update = data.ContainsKey("update") ? Json.Obj(data["update"]) : null;
                   if (update == null) return null;    // обновления нет — тишина
```

`api.py` отвечал `{"update_available": false, "version": ...}` — это объект **без** ключа
`update`, и WebView считал его ожидающим обновлением. Через 3 с автоклик звал
`loader:install` с `request_id = undefined`, `SelfUpdate.Install` падал и открывался
блокирующий диалог «Не удалось обновить лоадер. Запустите его снова.».

Что сделано:

* `api.py` → `GET /api/v1/loader-update` теперь отдаёт `{"update": null, ...}`
  (ровно то, что вендор возвращает для актуальной сборки), а
  `POST /api/v1/loader-update/complete` отвечает `ok`;
* `LoaderCrack.exe` (пересобран из `LoaderCrack.cs`) на старте удаляет
  `LoaderUpdateReceipt` из `HKCU\Software\Hidden\Loader` и игнорирует
  `--apply-loader-update` / `--cleanup-loader-update` — запущенная копия-`updater.exe`
  больше не может показать этот диалог;
* сломанный `__pycache__\api.cpython-315.pyc` удалён.

## Запуск

1. Двойной клик по `start.bat`.
2. Откроется окно лоадера. Ключ подставляется сам (сохранённый в реестре или
   `LOCAL-0000-0000-0000-0000`), вход выполняется автоматически.
3. В профиле — `lifetime`, срок до 2036 года, карточка игры.

Остановить: `stop.bat` (или просто закрыть окно + `stop.bat`, чтобы погасить сервер).

## Что именно сломано

`LoaderCrack.exe` — шим, который:

* загружает `Loader.exe` в свой процесс (`Assembly.Load`);
* подменяет `GameLoader.Config.Servers` на `http://127.0.0.1:8765`
  (обходит pinning, т.к. схема меняется на http);
* патчит IL трёх методов `GameLoader.ReleaseIntegrity` в образе до загрузки:
  `Verify`, `VerifyEnvelope`, `ValidateDigest` → `ret` (подпись и контрольная
  сумма больше не проверяются);
* пишет локальный ключ в `HKCU\Software\Hidden\Loader`, чтобы поле было заполнено;
* после старта UI сам заполняет форму и жмёт «Войти» через WebView2.

`api.py` — локальный HTTP-стенд на `127.0.0.1:8765`, отдаёт контракт
`/api/v1/auth|me|ping|games/{id}/manifest|package|launch`. Любой ключ = lifetime.
Лог запросов: `api.log`.

## Пакеты игры

Лоадер ставит и запускает то, что лежит в `packages\<id>.zip`:

```
packages\1.zip
  RobRun.exe        <- entry_file из манифеста
  ...остальные файлы
```

Кладёшь zip — в UI появляется карточка, «Играть» скачивает пакет, распаковывает
во временную папку и запускает `RobRun.exe`. `launch_args` и `run_steam`
задаются в `api.py` (функция `manifest`).

## Почему чит не внедрялся

Две причины, обе устранены:

1. **Пакет был от старушки 1.0.89.** В `packages\1.zip` лежал runtime 1.0.89
   (1.9 МБ), а сервер отдаёт 1.0.95 (16.3 МБ). Старый runtime не знает текущих
   оффсетов il2cpp — драйвер мапится, оверлей создаётся, но сцена не
   резолвится, и по факту «чита нет». Пакет заменён на актуальный, подпись
   совпадает с манифестом (`1742cfd6…7233`).
2. **Не было админ-токена.** `RobRun.exe` мапит драйвер через kdmapper; без
   elevation он кидает `std::runtime_error` и умирает с `0xC0000409`
   (`ucrtbase!abort`) ещё до создания оверлея. `start.bat` теперь сам просит
   UAC, всё дальше наследует админский токен.

## Если пишет «Сервер недоступен»

Это был не сервер, а мёртвый Python. `api.py` под `pythonw` падал на
`print()` сразу после `listening` — консоли нет, `sys.stdout` = `None`,
процесс тихо умирал, порт 8765 закрывался. Лоадер честно рисовал оффлайн.

Починено: `print` убран, любое падение пишется в `api_err.log`, повторный
запуск поверх живого сервера больше не плодит копии (`/api/v1/ping`).

Если снова оффлайн — сначала `api_err.log`, потом `api.log`.

## Запуск (по шагам, порядок важен)

1. `start.bat` — сам поднимет UAC, поднимет `api.py`, запустит лоадер,
   дождётся `RobRun.exe` и только потом откроет игру через Steam.
2. Игра должна стартовать **после** чита — иначе драйвер не успевает сесть.
3. `Insert` — меню, `End` — выгрузить.
4. `stop.bat` — гасит `RobRun.exe`, `LoaderCrack.exe` и сервер.

Если `RobRun.exe` не поднялся — смотри `loader_crack.log`, там последняя
причина. Самое частое: отказ от UAC или антивирус скушал драйвер из `%TEMP%`.

## Обновления

`start.bat` теперь сам проверяет обновление чита в консоли, до инжекта:

1. `update.ps1` берёт `license.json`, делает `POST /api/v1/auth`, читает
   подписанный манифест игры и сравнивает `package_sha256` с `packages\1.zip`.
2. Хэш не совпал — качает пакет с прогрессом, проверяет размер и SHA-256,
   проверяет, что внутри реально лежит `RobRun.exe`, и только потом
   подменяет zip. Старый остаётся как `packages\1.zip.bak`.
3. `real_manifest.json` обновляется, чтобы лоадер-фолбэк отдавал ту же
   сборку, а `%TEMP%\RobRun_inject` пересобирается из нового zip
   (`inject.ps1` сам видит, что кэш старее пакета).

Сеть/бэкенд недоступны — не беда: обновление помечается как неудачное, но
запуск продолжается на уже установленной сборке. Если вендор не ответил по
сети (а не отказал с 401/404), `update.ps1` и `inject.ps1` сами делают ещё
две попытки с паузой 2 секунды — такие обрывы у него бывают.

Отдельный случай — `403`. Это не сеть и не сбой: так вендор говорит, что ключ
не от этого ПК. Повторять бессмысленно, поэтому `update.ps1` сразу ставит
`logs\vendor_down.flag` (и снимает его при следующем успешном ответе), а
`start.bat` отдаёт обновление официальному лоадеру (`start_loader.bat`), если
рядом лежит `loader_key.txt`. Обновление при этом делает настоящий лоадер — с
его собственной подписью и своим апдейтером.

`chain.log` пишет время каждой строки (`[!date! !time!]`) уже в момент записи,
поэтому по нему видно, что именно съело время при провале.

Флаги:

| флаг | что делает |
|---|---|
| `start.bat noupdate` | не проверять обновление в этот раз |
| `start.bat rollback` | вернуть `packages\1.zip.bak` и не обновляться |

Если новая сборка не инжектится — `start.bat rollback`, и работает старая.

## Файлы

| файл | что это |
|---|---|
| `start.bat` / `stop.bat` | запуск/остановка |
| `SETUP.bat` | проверка ПК и режима обновления (ничего не меняет) |
| `update.ps1` | проверка/скачивание обновления пакета |
| `inject.ps1` | прямой инжект в `RobRun.exe` через named pipe (без UI) |
| `attach.ps1` | запуск игры через Steam и проверка оверлея |
| `start_loader.bat` | запасная цепочка: нетронутый официальный лоадер (обновляет сам) |
| `LoaderCrack.exe` | шим + автологин (фолбэк) |
| `LoaderCrack.cs` | исходник шима |
| `api.py` | локальный сервер лицензий |
| `Loader.exe` | оригинал (не тронут) |
| `license.json` | только `key` вендора |
| `hwid.txt` | id этой машины (его считает оригинальный лоадер) |
| `loader_key.txt` | официальный ключ для `start_loader.bat` (образец — `loader_key.example.txt`) |
| `api.log`, `loader_crack.log`, `logs\chain.log` | логи |
| `logs\inject.log` | что делал инжектор и что ответил рантайм |
| `logs\vendor_down.flag` | маркер: наш ключ на этом ПК не принимают, обновляет официальный лоадер |
| `packages\` | zip-пакеты (`1.zip`, `1.zip.bak`) |

## Если что-то не так

* Порт 8765 занят — `stop.bat`, потом снова `start.bat`.
* Поле ключа пустое и автологин не сработал — впиши любой ключ и нажми «Войти».
* Запуск без автологина: `LoaderCrack.exe --no-auto`.
* Свой ключ: `LoaderCrack.exe --key ТВОЙ-КЛЮЧ`.
